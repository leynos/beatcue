## Purpose / big picture

BeatCue is a Python library (and, later, a command-line tool) that analyses a
short video and writes time-coded cue sheets: WebVTT metadata cues, BeatCue
JSON, and later OpenTimelineIO markers. Its architecture is hexagonal: a pure
domain layer owns value objects and port protocols, an application layer
orchestrates use cases through those ports, outbound adapters implement the
ports with real infrastructure (FFmpeg, OpenCV, writers), and a composition
root wires concrete adapters into application services.

Today the repository contains only the empty package skeleton (`beatcue/domain`,
`beatcue/application`, `beatcue/adapters/inbound`, `beatcue/adapters/outbound`,
`beatcue/config`), each with an empty `__all__`, plus a `beatcue.hello()`
smoke function. No port, adapter, domain value, or media file exists. The
design-stage review (`docs/beatcue-logisphere-design-stage-review.md` §4
scenario A) warned that a well-architected skeleton might never touch a real
video file; this task is the mitigation it recommended (§8 step 5).

After this change, one command (`make test-media`) and the behavioural scenario
it runs prove that the architecture can touch real media and write a real cue
sheet:

```plaintext
generated 64×48, 4 fps, 1 s solid-colour MPEG-4 video (#3366cc)
        │
        ▼  MediaProbe port ── FfprobeMediaProbe ── CommandRunner port ── Cuprum ── ffprobe
MediaMetadata(duration=1.0, fps=4.0, 64×48, has_audio=False)
        │
        ▼  FrameSampler port ── FfmpegFrameSampler ── CommandRunner port ── Cuprum ── ffmpeg
FrameSample(timestamp=0.0, PixelBuffer 64×48 packed RGB)
        │
        ▼  application: build one synthetic cue from the sampled frame
AnalysisResult(media, cues=(Cue cue_000001 0.000→0.250 "Sampled frame",))
        │
        ▼  CueWriter port ── WebVttCueWriter
cues.vtt
```

The observable output is a WebVTT file such as:

```plaintext
WEBVTT
NOTE Generated by BeatCue

00:00:00.000 --> 00:00:00.250
{"id":"cue_000001","kind":"keyframe","label":"Sampled frame","confidence":1.0,"features":{"mean_b":201.0,"mean_g":100.0,"mean_r":49.0}}
```

The mean colour values come from real decoded pixels, so the file proves that a
frame really was sampled. The exact values depend on the FFmpeg build's colour
conversion, so the real-tools test asserts them within a tolerance (see
`Verification plan`).

Terms used throughout:

- *Port*: a `typing.Protocol` owned by `beatcue.domain` that describes a
  dependency the application needs (for example `MediaProbe`).
- *Adapter*: a class in `beatcue.adapters` that implements a port with real
  infrastructure.
- *Composition root*: `beatcue.config`, the only package allowed to import
  both application services and concrete outbound adapters.
- *Cuprum*: the typed, allowlisted subprocess library selected by design §16.
- *CmdMox*: the pytest plugin that intercepts external commands with shims on
  `PATH`, so adapter tests can verify exact argument vectors without real
  binaries.
- *Media-tools tier*: the tests marked `media_tools` that execute the real
  `ffprobe` and `ffmpeg` binaries. They skip when the binaries are absent,
  unless `BEATCUE_REQUIRE_MEDIA_TOOLS=1` is set, in which case absence (or any
  skip) fails the run.
- *Walking skeleton*: the thinnest end-to-end path through every layer that
  exercises real I/O. It is a proof of plumbing, not the analysis pipeline.

Preserved behaviour: `beatcue.hello()` and every existing test and gate keep
working. No public command-line interface (CLI) is added (decision D3).

## Constraints

- Read `AGENTS.md`, the `.rules/python-*.md` guides,
  `docs/developers-guide.md`, and
  `docs/complexity-antipatterns-and-refactoring-strategies.md` before editing
  code.
- Implementation begins only after the user approves this plan, including the
  provisional `CueKind.KEYFRAME` member (decision D8).
- The dependency rule is fixed by design §5 and enforced by Hecate
  (`pyproject.toml` `[tool.hecate]`, `make check-architecture`):
  `beatcue.domain` imports only the standard library and other domain modules;
  `beatcue.application` imports only domain and application modules; outbound
  adapters import domain, application, adapter, and infrastructure modules; only
  `beatcue.config` may import both application services and concrete outbound
  adapters. Do not weaken, reorder, or add `ignore_imports` to the Hecate
  policy.
- Port names and signatures in design §8 are normative: `MediaProbe.probe`,
  `FrameSampler.sample`, and `CueWriter.write`, exactly as reproduced in
  `Interfaces and dependencies`. `CommandRunner` is the design's named
  subprocess port. Do not rename these or change their parameters.
- Domain value objects must not carry NumPy, OpenCV, Cuprum, or other
  infrastructure types (design §§7–8). Pixel processing stays out of the
  domain: ADR 0001 keeps raw-frame computation in adapters, so the only pixel
  arithmetic this plan adds (channel means) lives in the application module as
  a proof-only helper (decision D12).
- All external commands run through the Cuprum-backed `CommandRunner` adapter.
  No `subprocess`, `os.system`, `os.popen`, `os.spawn*`, `os.exec*`, `pty`, or
  `asyncio.create_subprocess_*` anywhere in `beatcue/` except inside Cuprum
  itself (design §16; developers' guide "Subprocess tooling").
- Boundary package `__init__.py` files keep `__all__: list[str] = []`;
  `tests/test_package_skeleton.py` asserts this. Public names are exported from
  submodules only.
- Every new production module declares `__all__` naming its public symbols.
  Planning probe P4 showed that the strict Skylos gate treats names in a
  module's `__all__` as live (decision D7).
- No file may exceed 400 lines (`AGENTS.md`; Pylint `max-module-lines`).
  Respect Ruff `mccabe` max-complexity 8 and Pylint `max-args = 4` and
  `max-positional-arguments = 4`. Pylint (`PYLINT_TARGETS ?= beatcue tests`) and
  `interrogate` at 100 % (`INTERROGATE_TARGETS ?= beatcue scripts tests`) both
  scan `tests/`, so every test function, fixture, step function, in-test fake,
  and fake method needs a docstring, and BDD step functions must take at most
  four arguments (parse composite values such as `rgb(51,102,204)` into one
  value object).
- `scripts/uv_gate.py` is vendored byte for byte (its module docstring);
  never edit it locally. Run every gate with `FORCE_COLOR` unset (see
  `Surprises & discoveries`).
- Error classes end in `Error`, are raised with `raise … from …` when
  translating, and messages are assigned to a variable before raising (Ruff
  `EM`, `TRY`;
  `.rules/python-exception-design-raising-handling-and-logging.md`).
- Command timeout plus cancellation grace must stay below the pytest timeout
  of 30 seconds (`pyproject.toml` `[tool.pytest.ini_options]`): tests and the
  media-tools scenarios construct the skeleton with
  `command_timeout_seconds=10.0`, and the runner's grace is 0.5 seconds.
- Do not implement scope owned by later roadmap items beyond the minimum the
  skeleton needs: cue sorting and fusion invariants and the remaining design §7
  fields (2.1.x), BeatCue JSON (2.2.1), partial-output marking and the full
  WebVTT contract (2.2.2), the library writer API (2.2.3), the CmdMox fixture
  matrix (1.4.3), the production ffprobe adapter matrix (3.1.1),
  timestamp-faithful and efficient frame sampling (3.1.2), and any Cyclopts CLI
  (3.3.x).
- Authorized dependency change: add the self-reference `"beatcue[core]"` to
  the `dev` dependency group (decision D5). No new third-party distribution.
- Authorized CI change: one new job in `.github/workflows/ci.yml`, pinned to
  `runs-on: ubuntu-24.04`, that installs Ubuntu's `ffmpeg` package and runs
  `make test-media` (decision D4). `.github/workflows/coverage-main.yml` is not
  changed.
- Do not edit completed ExecPlans; only add this plan's entry to
  `docs/contents.md`.
- Spelling follows en-GB-oxendict (`-ize`, `-yse`, `-our`) in comments and
  documentation.

## Risks

- Risk: FFmpeg's YUV→RGB conversion differs between versions, so exact pixel
  values vary across hosts. Severity: medium. Likelihood: high. Mitigation: the
  media-tools tier asserts mean colour within ±12 of the source colour
  `#3366cc` (51, 102, 204); exact values are snapshotted only for in-memory and
  CmdMox paths. Planning probes P1 and P8 observed (49, 100, 201) with FFmpeg
  5.1.9 for both H.264 and MPEG-4 Part 2 encodings.

- Risk: the media-tools tier silently skips or deselects, making the proof
  vacuous. Severity: high. Likelihood: medium. Mitigation: four layers. Absent
  tools fail when `BEATCUE_REQUIRE_MEDIA_TOOLS=1`; a
  `pytest_runtest_makereport` hook turns any skipped `media_tools` test into a
  failure under the same switch; `make test-media` uses `--strict-markers` so a
  mistyped tag fails, and pytest exits with status 5 when `-m media_tools`
  selects nothing; a unit test asserts both real-tool scenarios in the feature
  file carry `@media_tools`.

- Risk: Cuprum 0.1.0 captures output only as decoded text and has no timeout
  argument (verified in the locked Cuprum 0.1.0 wheel, `cuprum/sh.py`,
  `ExecutionContext` and `SafeCmd.run`). Severity: medium. Likelihood: certain.
  Mitigation: FFmpeg writes each sampled frame as a PPM file into a private
  temporary directory (decision D2); timeouts wrap `SafeCmd.run` in
  `asyncio.wait_for`, whose cancellation makes Cuprum send `SIGTERM` and
  escalate to `SIGKILL` after `cancel_grace` (decision D6). Cuprum 0.2.0b2,
  seen elsewhere on this host, adds byte capture and native timeouts; ADR 0011
  records it as the option to revisit once 0.2 is stable.

- Risk: the skeleton sampler becomes production by inertia.
  Severity: high. Likelihood: medium. Mitigation: at the design §10.1 bounds
  (600 s at 4 fps) it would start 2,400 FFmpeg processes, re-decode from the
  previous keyframe on every seek, and move about 15 GB of PPM data for 1080p
  input. It is capped by `max_samples=2400`, ADR 0011 labels it "skeleton only,
  not for `analyse`", and roadmap 3.1.2 gains the acceptance criterion that
  sparse or variable-frame-rate streams must not stop sampling early.

- Risk: `asyncio.run` fails when the caller already runs an event loop (for
  example Jupyter). Severity: medium. Likelihood: low for the skeleton.
  Mitigation: the runner checks `asyncio.get_running_loop()` before creating
  any coroutine and raises `CommandRunnerContextError` with an actionable
  message; a test covers it.

- Risk: CmdMox `runs` handlers execute inside the pytest process on the IPC
  thread, so a sleeping handler cannot exercise timeouts. Severity: medium.
  Likelihood: certain. Mitigation: the timeout test runs the real `sleep`
  program through a runner whose allowed programs are `{"sleep"}`.

- Risk: CmdMox shims read standard input to end of file unless it is a
  terminal; Cuprum does not set the child's standard input. Under `pytest -s`
  with a never-closing pipe as standard input (as in some agent harnesses) a
  shimmed command hangs. Severity: low. Likelihood: low. Mitigation: never run
  CmdMox tests with `-s`; documented in the developers' guide.

- Risk: the self-referencing `beatcue[core]` entry in the `dev` group changes
  what `make build` and the CI coverage action install. Severity: medium.
  Likelihood: low. Mitigation: planning probe P3 showed `uv` locks a
  self-referencing extra in a dependency group; `EP-M1` runs `uv lock --check`
  and the full gates before any adapter code.

- Risk: Skylos treats `__all__` exports as live, which could hide genuinely
  dead public names. Severity: low. Likelihood: medium. Mitigation:
  `Outcomes & retrospective` lists any exported name whose only callers are
  tests, and removes it.

- Risk: Ubuntu's `ffmpeg` package changes under the CI job.
  Severity: medium. Likelihood: low. Mitigation: the job pins
  `runs-on: ubuntu-24.04` (FFmpeg 6.1 series), prints `ffmpeg -version` and
  `ffprobe -version`, retries `apt-get` (`-o Acquire::Retries=3`), and runs
  separately from the coverage lane so a mirror outage cannot affect coverage
  publication.

## Surprises & discoveries

- Observation: Cuprum 0.1.0 captures standard output only as decoded text
  (`ExecutionContext.encoding`, default `utf-8`, `errors="replace"`) and has no
  timeout argument; `SafeCmd.run_sync` is `asyncio.run(self.run(…))` and so
  also has no timeout. Evidence: Cuprum 0.1.0 wheel (`uv.lock` entry `cuprum`
  0.1.0), `cuprum/sh.py` `ExecutionContext`, `SafeCmd.run`, and
  `SafeCmd.run_sync`. Impact: decisions D2 and D6.

- Observation: FFmpeg writes nothing and exits 0 when asked for a frame past
  the end of the stream; with the `image2` muxer it does not create the output
  file at all. Evidence: planning probes P1 and P2. Impact: the sampler's
  end-of-stream rule is "exit 0 and no output file".

- Observation: `ffprobe` on a non-media file exits 1 and still prints an empty
  JSON object (`{}`) to standard output. Evidence: probe P2. Impact: the probe
  adapter checks the exit status before parsing and treats a document without a
  usable video stream as an error.

- Observation: the strict Skylos gate treats names listed in a module's
  `__all__` as live and reports unexported unused classes and functions.
  Evidence: probe P4. Impact: production modules export their public names
  (D7); inner-layer milestones pass `make lint` before the composition root
  exists.

- Observation: `make test` and the CI coverage action install only the `dev`
  dependency group, so Cuprum and Cyclopts are absent from the test
  environment; any `uv_gate prepare` run also removes extras that a manual
  `uv sync --extra …` installed. Evidence: `Makefile` `.deps`
  (`uv_gate prepare --group dev`); `leynos/shared-actions`
  `generate-coverage/scripts/run_python.py` (`uv sync --inexact`); Cuprum
  disappeared from `.venv` after the first `make fmt` during planning. Impact:
  decision D5.

- Observation: with `FORCE_COLOR=1` in the environment, `uv cache dir` prints
  ANSI colour codes, and `scripts/uv_gate.py` (`_query_cache_dir`) uses that
  output as a relative path, creating an ignored directory named
  `\033[36m/home/…/.cache/uv` inside the worktree and a cold, online uv cache.
  Its Markdown files then break `make spelling`. Evidence: during planning the
  directory appeared twice (207 MB and 33 MB) and `make spelling` reported a US
  spelling inside it; running gates as `env -u FORCE_COLOR make …` avoids it.
  Impact: every gate command in this plan is prefixed with
  `env -u FORCE_COLOR`; remove any such directory with `rm -rf -- $'\033[36m'`
  before gating. `uv_gate.py` is vendored, so the fix belongs upstream (it
  should disable uv's colour output when it queries the cache directory);
  report it to the user rather than patching locally.

## Decision log

- D1. Decision: add a domain-owned `CommandRunner` port and a single
  `CuprumCommandRunner` adapter; the ffprobe probe and ffmpeg sampler depend on
  the port, not on Cuprum. The runner is constructed with
  `allowed_programs: frozenset[str]` (no default) and builds its Cuprum
  `ProgramCatalogue` internally; each command-using adapter exports a
  `REQUIRED_PROGRAMS` constant, and the composition root unions them.
  Rationale: design §16 makes the subprocess boundary one outbound adapter and
  names `CommandRunner` as the replacement seam; design §6 lists
  `commands_cuprum.py`. Assembling the allowlist in the composition root (panel
  finding, Pandalump) ties each program name to the adapter that needs it and
  stops every later adapter (3.1.3, `nixie`) from editing the runner module.
  Rejected: media adapters calling Cuprum directly (duplicated catalogue,
  timeout, and error translation; rework at 3.1.1 and 3.1.3). Date/Author:
  2026-11-17, planning agent; revised after panel review.

- D2. Decision: the walking-skeleton `FrameSampler` is `FfmpegFrameSampler`,
  which runs one `ffmpeg` invocation per sample time (`t_i = i / sample_fps`),
  asking for one frame as a binary PPM (`P6`) file in a private temporary
  directory, reading it, deleting the directory, and yielding a `FrameSample`.
  It stops when FFmpeg exits 0 without creating the file, and raises
  `FrameSamplingError` once more than `max_samples` (default 2,400, the design
  §10.1 frame budget) frames would be produced. Rationale: Cuprum 0.1.0 cannot
  capture binary output; PPM is self-describing; one invocation per frame keeps
  the generator lazy and resource-free between yields, so abandoning it after
  the first frame leaks nothing. Cost at the §10.1 bounds is about 2,400
  processes and about 15 GB of temporary-file traffic for 1080p input, so this
  adapter is skeleton-only. Rejected alternatives, recorded in ADR 0011: OpenCV
  `VideoCapture` (the main candidate for 3.1.2, but it bypasses the Cuprum
  boundary the roadmap asks to prove and pulls the `media` extra into the dev
  group); one FFmpeg call with the `fps` filter writing numbered PPMs (eager
  decoding, disk proportional to duration × rate, timestamps that do not match
  `i / f`); Latin-1 text capture (correct but couples correctness to a decoding
  trick). Date/Author: 2026-11-17, planning agent; cap and cost added after
  panel review.

- D3. Decision: satisfy "one command or test" with `make test-media` and the
  behavioural scenario it runs; do not add a public CLI. Rationale: roadmap
  3.3.1 owns the Cyclopts root command and its Rich and `--json` contracts; a
  CLI now would pre-empt that design and require users' guide documentation of
  a throwaway command. The behavioural test acts as the library caller in
  design Figure 1. Probe P4 removed the only technical reason to add a runtime
  caller early. All three panel reports endorsed this. Date/Author: 2026-11-17,
  planning agent.

- D4. Decision: introduce a `media_tools` pytest marker and tier switch.
  `BEATCUE_REQUIRE_MEDIA_TOOLS` unset, empty, or `0` means skip when `ffprobe`
  or `ffmpeg` is not on `PATH`; `1` means fail instead, and also turns any
  skipped `media_tools` test into a failure; any other value fails with a
  message naming the accepted values. CI runs `make test-media` in a separate
  job pinned to `ubuntu-24.04`, after installing FFmpeg from the Ubuntu
  archive, and placed so it cannot affect the coverage lane. Rationale: neither
  the development host nor the GitHub runner image has FFmpeg; a plain skip
  would make the proof vacuous, and a hard requirement would make `make test`
  unusable on contributor machines. Pinning the runner satisfies the
  developers' guide rule that CI tools name exact versions as far as the Ubuntu
  archive allows. Installing FFmpeg in the coverage lane was rejected because a
  CmdMox test that forgot a mock would silently use the real binary there
  (panel finding, Buzzy Bee). Date/Author: 2026-11-17, planning agent; revised
  after panel review.

- D5. Decision: add `"beatcue[core]"` to `[dependency-groups].dev`.
  Rationale: `make build`, `make test`, and the CI coverage action all sync
  only the `dev` group; without Cuprum the adapters cannot be imported in
  tests. The self-reference keeps the `core` extra as the single source of
  runtime pins. Rejected: duplicating `cuprum>=0.1.0` in `dev` (two sources of
  truth) and adding `--extra core` to the Makefile (does not reach the shared
  coverage action). Date/Author: 2026-11-17, planning agent.

- D6. Decision: `CommandRequest` carries an explicit `timeout_seconds`;
  `CuprumCommandRunner` refuses to run inside an already running event loop
  (`CommandRunnerContextError`), otherwise wraps `SafeCmd.run` in
  `asyncio.wait_for` inside `asyncio.run`, and translates `TimeoutError` into
  `CommandTimeoutError`. Missing or non-executable programs
  (`FileNotFoundError`, `PermissionError`, `OSError` with `ENOEXEC`) become
  `CommandUnavailableError`. The allowlist is enforced by building commands with
  `cuprum.sh.make(program, catalogue=…)`, which raises `UnknownProgramError`;
  the context-variable allowlist (`cuprum.scoped`) is not relied upon because
  an empty parent allowlist is permissive. Rationale: design §16 requires
  explicit timeouts and a termination request before escalation; Cuprum
  implements termination on task cancellation via
  `ExecutionContext.cancel_grace`. Date/Author: 2026-11-17, planning agent;
  loop guard and error mapping added after panel review.

- D7. Decision: every new production module declares `__all__` with its
  public names; boundary `__init__.py` files stay empty. Rationale: probe P4
  (Skylos liveness via `__all__`) and the existing
  `tests/test_package_skeleton.py` contract. Date/Author: 2026-11-17, planning
  agent.

- D8. Decision (provisional; requires explicit user approval): add
  `CueKind.KEYFRAME = "keyframe"` for the synthetic cue, and mark the cue
  synthetic in its provenance. Rationale: none of the design §7 kinds describes
  "a frame was sampled here"; reusing `cut` would make the skeleton lie about
  its evidence, and `caption` would breach the invariant that semantic
  annotations cannot create timing cues. The panel (Telefono, Wafflecat) noted
  that design §§9 and 12 use "keyframe" for semantic selection points, not
  cues, and that cue kinds become public through BeatCue JSON (2.2.1) and
  `agent-context`. The member is therefore marked provisional in design §7 and
  ADR 0011: roadmap 2.2.1 must adopt it (amending §12) or remove it before the
  JSON schema is frozen. Alternative offered to the user: a cue kind such as
  `frame_sample`, or no new member with the skeleton reusing an existing kind;
  both are inferior to an explicitly provisional `keyframe`. Date/Author:
  2026-11-17, planning agent; status set to provisional after panel review.

- D9. Decision: the WebVTT writer always emits `HH:MM:SS.mmm` timestamps
  (two or more hour digits), rounds the exact value
  `fractions.Fraction(seconds) * 1000` to the nearest millisecond with ties
  away from zero, and guarantees end greater than start: when the rounded end
  does not exceed the rounded start it widens the end to `start + 1 ms`, or, if
  that would pass the rounded media duration, moves the start back 1 ms.
  Payload JSON is produced by
  `json.dumps(…, ensure_ascii=True, separators=(",", ":"), allow_nan=False)`
  followed by `.replace(">", "\u003e")`, so `"a --> b"` is written as
  `"a --\u003e b"`. Rationale: WebVTT requires the end timestamp to "be greater
  than the start time offset of the cue" and forbids `-->` in cue payloads (W3C
  WebVTT, revision `0648025`, "WebVTT cue timings" and cue payload rules,
  verified 2026-11-17). Design §13.2 ("enforces `start <= end`") and the §17
  named invariant ("never move a cue start after its end") would admit invalid
  zero-length cues; both are corrected in the design document (not in ADR 0011,
  which covers the subprocess boundary). Point cues such as beats will make
  widening the normal case. The `features` payload key goes beyond the §13.2
  example; 2.2.2 may keep or drop it. Date/Author: 2026-11-17, planning agent;
  duration edge and placement revised after panel review.

- D10. Decision: the writer renders the whole document before touching the
  file system, writes it to a temporary file in the target's directory, and
  then publishes it with `os.link(temporary, target)` when overwriting is not
  allowed (atomic, refuses an existing target; `FileExistsError` becomes
  `OutputExistsError`) or `os.replace(temporary, target)` when
  `OutputTarget.overwrite` is true. The temporary file is unlinked in a
  `finally` block. Text is UTF-8 with LF line endings. Rationale: design §18
  ("Output path exists → writer refuses to overwrite unless `--force`"); the
  first draft's exclusive-create mode could leave a partial file after a disk
  error, after which every retry would fail with `OutputExistsError` (panel
  finding, Doggylump). Date/Author: 2026-11-17, planning agent; revised after
  panel review.

- D11. Decision: record decisions D1, D2, D4, D5, D6, D12, and the skeleton's
  lifecycle in ADR 0011, "Walking-skeleton subprocess boundary and media-tools
  test tier", referenced from design §§6, 8, 16, and 17. D9 is recorded in
  design §§13.2 and 17 directly. Rationale: they change design guidance that
  later roadmap items build on. Date/Author: 2026-11-17, planning agent.

- D12. Decision: compute the synthetic cue's channel means in the application
  module (`channel_means`, using `sum(data[c::3])` per channel), not in the
  domain, and mark it proof-only in ADR 0011. Rationale: ADR 0001 keeps
  raw-frame computation inside adapters, while design §8 already passes
  `FrameSample` pixels across the `FrameSampler` port and the roadmap asks the
  application layer to create the cue. Keeping the arithmetic out of the domain
  avoids setting a precedent; 3.2.1 computes real colour features in an
  adapter. The tension between design §8 and ADR 0001 is an open question for
  the design owner before 3.1.2. Date/Author: 2026-11-17, planning agent, after
  panel review.

- D13. Decision: compact the skeleton. Domain code lives in four modules that
  match design §6 names (`errors.py`, `media.py`, `cues.py`, `ports.py`); the
  media fixture is generated at test time with FFmpeg's built-in `mpeg4`
  encoder rather than committed; ffprobe variants are inline test data apart
  from one captured document; cue sorting and the full `TimeRange` search are
  left to 2.1.1, and Unicode and long-duration WebVTT snapshot variants to
  2.2.2 (the escaping and widening properties stay here). Rationale: panel
  finding (Wafflecat, Dinolump) that the first draft exceeded its own file
  tolerance and stretched a "narrow proof"; generated fixtures match design §17
  and the developers' guide ("small generated media fixtures"). The proof still
  depends on real FFmpeg in both cases. Date/Author: 2026-11-17, planning
  agent, after panel review.

- D14. Decision: domain records are frozen, slotted, keyword-only dataclasses;
  `Cue.features` and the provenance fields are stored as key-sorted tuples of
  `(name, value)` pairs, validated and normalized in `__post_init__`.
  Rationale: the first draft's `types.MappingProxyType` copies make frozen
  values unpicklable, un-deep-copyable, and unhashable on Python 3.14 (panel
  finding, Telefono, verified by experiment); keyword-only fields let 2.1.1 add
  the remaining design §7 fields without breaking construction sites.
  Date/Author: 2026-11-17, planning agent, after panel review.

- D15. Decision: `FrameSample.timestamp_seconds` means the decoded frame's
  presentation timestamp. The skeleton sampler approximates it with the
  requested seek time and the synthetic cue records
  `timestamp_source="requested_seek"` in its provenance. Rationale: timestamp
  alignment is the failure named in the design-stage review's scenario A;
  fixing the field's meaning now stops it drifting when 3.1.2 supplies true
  timestamps. Date/Author: 2026-11-17, planning agent, after panel review.

- D16. Decision: `beatcue/config/compose.py` imports the Cuprum adapter lazily
  inside `build_walking_skeleton` (via `importlib.import_module`) and turns
  `ImportError` into `DependencyUnavailableError` naming the `core` extra.
  Rationale: design §6.1 requires missing optional dependencies to be
  capability errors rather than import-time crashes; D5 would otherwise hide
  the crash in every test environment. Date/Author: 2026-11-17, planning agent,
  after panel review.

## Verification plan

### Abstract model

The walking skeleton is a straight-line pipeline over four ports:

1. `probe(source) -> MediaMetadata m` with `m.duration_seconds > 0`,
   `m.fps > 0`, `m.width > 0`, `m.height > 0`, all finite.
2. `sample(source, sample_fps=f)` yields `FrameSample`s whose timestamps are
   `t_i = i / f` for `i = 0, 1, …` until FFmpeg reports end of stream or
   `max_samples` is exceeded. The application consumes only the first sample
   `s_0`.
3. `build_sampled_frame_cue(m, s_0) -> Cue c` with
   `c.time = TimeRange(t_0, min(t_0 + 1 / m.fps, m.duration_seconds))`,
   `c.id = "cue_000001"`, `c.kind = KEYFRAME`, `c.confidence = 1.0`, features
   `mean_r`, `mean_g`, `mean_b` computed from `s_0`'s pixels and rounded to
   three decimal places, and provenance recording `synthetic=True`,
   `stage="walking_skeleton"`, and `timestamp_source="requested_seek"`.
4. `write(AnalysisResult(media=m, cues=(c,), provenance=…), target)` renders
   WebVTT text and publishes it atomically.

Failure transitions: missing or non-executable program →
`CommandUnavailableError`; program outside the allowlist →
`CommandNotAllowedError`; timeout → `CommandTimeoutError`; called inside a
running event loop → `CommandRunnerContextError`; `ffprobe` non-zero exit,
malformed JSON, or no usable video stream → `MediaProbeError`; `ffmpeg`
non-zero exit, malformed PPM, or sample cap exceeded → `FrameSamplingError`; no
first sample → `EmptyFrameStreamError`; existing target without overwrite →
`OutputExistsError`; `core` extra missing → `DependencyUnavailableError`.

Error hierarchy (`beatcue/domain/errors.py`): `BeatCueError(Exception)` with
families `InvalidDomainValueError(BeatCueError, ValueError)`,
`DependencyUnavailableError` (parent of `CommandUnavailableError`),
`CommandError` (parent of `CommandNotAllowedError`, `CommandTimeoutError`,
`CommandRunnerContextError`), `InputMediaError` (parent of `MediaProbeError`,
`FrameSamplingError`, `EmptyFrameStreamError`), and `OutputError` (parent of
`OutputExistsError`). Command errors carry the `CommandRequest`;
`MediaProbeError` and `FrameSamplingError` carry `source`, `reason`, and the
failing `CommandOutcome` when there is one (design §18: "a validation error
with the failed command result"). These families let 3.3.x map exit codes by
family (§14: `4` means dependency).

### Invariants and lemmas

- `INV-time-range` (REQ-cue): `TimeRange(start_seconds=…, end_seconds=…)`
  exists only when both are finite and `0 <= start <= end`; otherwise
  construction raises `InvalidDomainValueError`.
- `INV-media` (REQ-probe): `MediaMetadata` exists only with finite positive
  duration and frame rate and positive integer dimensions.
- `INV-pixel-buffer` (REQ-sample): `PixelBuffer(width, height, data)` exists
  only when `width > 0`, `height > 0`, and `len(data) == width * height * 3`.
- `INV-cue` (REQ-cue): a `Cue` has a non-empty id and label, a finite
  confidence in `[0.0, 1.0]` (design §§7, 17), finite feature values, and
  unique, key-sorted feature and provenance names; it survives a pickle round
  trip and is hashable.
- `INV-result` (REQ-cue): `AnalysisResult` rejects any cue whose range ends
  after `media.duration_seconds`.
- `INV-channel-means` (REQ-cue): for any valid `PixelBuffer`,
  `channel_means` returns three values in `[0, 255]` equal to the arithmetic
  mean of each channel.
- `INV-cue-within-media` (REQ-cue): the synthetic cue satisfies
  `0 <= start < end <= duration` whenever `t_0 < duration`.
- `INV-ppm-roundtrip` (REQ-sample): parsing a well-formed binary PPM
  (`P6`, maximum value 255) returns exactly its width, height, and pixel bytes;
  any header that is not `P6`, any maximum value other than 255, any malformed
  number, and any payload length mismatch raise `FrameSamplingError`.
- `INV-probe-mapping` (REQ-probe): a well-formed ffprobe document maps to
  `MediaMetadata` using the first video stream whose `disposition.attached_pic`
  is 0; `fps` is its `avg_frame_rate` fraction, falling back to `r_frame_rate`
  when the average is `0/0` or absent; duration is `format.duration`, falling
  back to the stream duration when the format value is absent or `N/A`;
  `has_audio` is true exactly when an audio stream is present. A document with
  no such video stream (including `{}` and cover-art-only audio files) raises
  `MediaProbeError`.
- `INV-vtt-timestamp` (REQ-write): `format_timestamp(ms)` produces
  `HH:MM:SS.mmm` with at least two hour digits, and an independent parser in
  the test recovers `ms` exactly for all `0 <= ms < 10^9`.
- `INV-vtt-rounding` (REQ-write): `to_milliseconds(seconds)` equals
  `Decimal(seconds) * 1000` quantized to an integer with `ROUND_HALF_UP`
  (`Decimal(float)` is exact, so the oracle is independent of the
  implementation's `Fraction` arithmetic).
- `INV-vtt-order` (REQ-write): every rendered cue has end strictly greater
  than start, and neither exceeds the rounded media duration.
- `INV-vtt-payload` (REQ-write): every payload line is ASCII, contains no
  `-->`, contains no line terminator, and `json.loads` recovers the cue's id,
  kind, label, confidence, and features exactly.
- `INV-no-subprocess` (REQ-boundaries): no module under `beatcue/` imports
  `subprocess` or `pty`, or calls `os.system`, `os.popen`, `os.spawn*`,
  `os.exec*`, or `asyncio.create_subprocess_*`.
- `INV-tier-switch` (REQ-proof): for each value of
  `BEATCUE_REQUIRE_MEDIA_TOOLS` in {unset, `""`, `"0"`, `"1"`, `"yes"`} and
  each presence combination of `ffprobe` and `ffmpeg`, the tier decision is
  run, skip, or fail exactly as decision D4 states.
- `L-sampler-lazy` (REQ-sample): `FfmpegFrameSampler.sample` invokes
  `ffmpeg` exactly once before yielding the first frame, holds no open file or
  temporary directory between yields, stops after the first invocation that
  exits 0 without an output file, and raises `FrameSamplingError` on the
  invocation after `max_samples` frames.
- `L-runner-translation` (REQ-failures): `CuprumCommandRunner.run` maps a
  missing executable, a disallowed program, a timeout, and a running event loop
  to the four corresponding errors, and returns a `CommandOutcome` (never
  raises) for non-zero exits.
- `L-writer-atomic` (REQ-failures): after any failed `write`, the target is
  either absent or byte-identical to its previous content, and no temporary
  file remains in the directory.
- `L-composition` (REQ-boundaries, REQ-capability): `build_walking_skeleton`
  returns a service whose probe and sampler share one runner allowed exactly
  `{"ffprobe", "ffmpeg"}`, and raises `DependencyUnavailableError` when Cuprum
  cannot be imported.

### Axioms (trusted, not verified here)

- `AXIOM-ffprobe-json`: `ffprobe -v error -of json -show_entries … FILE`
  prints a JSON object with the requested `streams` and `format` entries for
  valid media and exits non-zero for unreadable or non-media input (FFmpeg
  documentation, "ffprobe" writers section; probes P2 and P8).
- `AXIOM-ffmpeg-seek`: input seeking (`-ss` before `-i`) is frame-accurate
  when transcoding (FFmpeg wiki "Seeking", since FFmpeg 2.1).
- `AXIOM-ffmpeg-eos`: requesting one frame beyond the end of the stream exits
  0 and, with `-f image2 -update 1`, creates no output file (probe P2, FFmpeg
  5.1.9). The CI job's FFmpeg (Ubuntu 24.04, 6.1 series) is exercised by the
  media-tools tier, which would fail if this changed.
- `AXIOM-ppm`: FFmpeg's `ppm` encoder with `-pix_fmt rgb24` writes
  `P6\n<width> <height>\n255\n` followed by `width * height * 3` bytes (probe
  P2 header dump).
- `AXIOM-cuprum`: Cuprum 0.1.0 resolves the program name on `PATH`, raises
  `FileNotFoundError` from process creation when it is missing (confirmed by
  P6), and terminates the child process when the awaiting task is cancelled
  (source reading; confirmed by P7).
- `AXIOM-cmdmox`: CmdMox shims on `PATH` intercept any process started by
  name, including Cuprum's (source reading; confirmed by P5).
- `AXIOM-webvtt`: the W3C WebVTT syntax (Candidate Recommendation Draft,
  revision `0648025`) requires the `WEBVTT` signature, forbids `-->` in cue
  payloads and comments, makes hours optional with two or more digits, and
  requires cue end times greater than start times.

### Methods per obligation

- Obligation: `INV-time-range`, `INV-media`, `INV-pixel-buffer`, `INV-result`.
  Method: parameterized pytest over the partition of valid and invalid values
  (zero, negative, NaN, infinity, wrong length, end past duration). Rationale:
  these are finite partitions at this stage; the generated `TimeRange` search
  belongs to 2.1.1 (D13). Artefacts: `tests/test_domain_media.py`,
  `tests/test_domain_cues.py`. Evidence:
  `env -u FORCE_COLOR python3 scripts/uv_gate.py run -- pytest -n0
  tests/test_domain_cues.py`
  fails with `ModuleNotFoundError` before the module exists and passes after.
  Non-vacuity: each row names its class; seeded fault (changing `<=` to `<` in
  the `TimeRange` guard) must fail the `(0.0, 0.0)` row.

- Obligation: `INV-cue`.
  Method: Hypothesis property over feature dictionaries
  (`st.dictionaries(st.text(min_size=1), st.floats(allow_nan=True,
  allow_infinity=True))`)
  and confidence floats, plus named examples. Artefact:
  `tests/test_domain_cues.py`. Non-vacuity: `hypothesis.event()` labels
  accepted and rejected inputs and `@example`s pin both (`confidence=1.0`,
  `confidence=1.0000001`, `{"a": nan}`); the pickle and hash checks fail under
  the first draft's `MappingProxyType` representation.

- Obligation: `INV-channel-means`.
  Method: Hypothesis property with an independent oracle (`statistics.fmean`
  over per-pixel tuples built in the test). Domain: widths and heights in
  `[1, 16]`, random byte strings of the exact length. Artefact:
  `tests/test_walking_skeleton_application.py`. Non-vacuity: a solid-colour
  example `(51, 102, 204)` must return exactly that triple; seeded fault
  (dividing by `width * height * 3`) must fail.

- Obligation: `INV-cue-within-media`.
  Method: Hypothesis property over `duration in (0, 600]`, `fps in (0, 120]`,
  `t_0 in [0, duration)`. Artefact:
  `tests/test_walking_skeleton_application.py`. Non-vacuity: explicit example
  where `t_0 + 1/fps > duration` exercises the clamp; removing the `min` must
  fail it.

- Obligation: `INV-ppm-roundtrip`.
  Method: Hypothesis round trip with a test-local PPM encoder (independent of
  the parser) and a parameterized malformed-header table (`P3`, maximum value
  65535, truncated payload, trailing bytes, missing whitespace, non-numeric
  width, zero width). Artefact: `tests/test_frames_ffmpeg.py`. Non-vacuity: the
  malformed table has at least one row per rejection branch; deleting the
  payload-length check must fail the truncated row.

- Obligation: `INV-probe-mapping`.
  Method: parameterized pytest over documents derived in the test from the
  captured document `tests/fixtures/ffprobe/solid-colour-mpeg4.json`
  (unchanged; plus an audio stream; `avg_frame_rate` `0/0`; format duration
  `N/A`; cover art first with `attached_pic: 1`; audio only; `{}`), and a
  Hypothesis property over `num/den` rate strings. Artefact:
  `tests/test_media_ffprobe.py`. Non-vacuity: each fallback branch has a
  dedicated row whose expected value differs from the primary branch.

- Obligation: `INV-vtt-timestamp`, `INV-vtt-rounding`, `INV-vtt-order`, and
  `INV-vtt-payload`. Method: Hypothesis properties with an independent
  regular-expression timestamp parser, the `Decimal` rounding oracle, and
  `json.loads`; syrupy snapshots for two canonical documents (one ordinary cue;
  one zero-length cue at the end of the media, which exercises both widening
  branches). Artefacts: `tests/test_writers_webvtt.py` and
  `tests/__snapshots__/test_writers_webvtt.ambr`. Non-vacuity:
  `@example(label="a --> b")` and `@example(label="é\n")` are always run; a
  named assertion checks that the raw payload of `"a --> b"` contains
  `--\u003e` and not `-->`; seeded fault (removing the `>` escape) must fail
  `INV-vtt-payload`; seeded fault (dropping the widening) must fail
  `INV-vtt-order` on `TimeRange(start_seconds=1.0, end_seconds=1.0004)`;
  `@example(seconds=0.0005)` pins the tie rule.

- Obligation: `L-runner-translation`.
  Method: CmdMox-backed tests for success (exact argument vector recorded by
  CmdMox) and non-zero exit; a runner allowed `{"beatcue-missing-tool"}` for
  the missing program; a disallowed program; the real `sleep 30` with a 1 s
  timeout through a runner allowed `{"sleep"}`; and a call made from inside
  `asyncio.run` for the running-loop guard. Artefact:
  `tests/test_commands_cuprum.py`. Non-vacuity: each error test asserts the
  specific exception type and its `request.program`; the timeout test also
  asserts the call returns within `timeout + grace + 2` seconds, which an
  implementation that waited for `sleep` to finish would fail.

- Obligation: `L-sampler-lazy`.
  Method: CmdMox `runs` handler that writes a PPM file to the path in
  `invocation.args[-1]` for the first two calls and writes nothing on the
  third; the test counts invocations after `next()` and after exhaustion, and
  checks that no `beatcue-frame-*` temporary directory exists after each yield;
  a second test with `max_samples=1` and a handler that always writes a frame
  expects `FrameSamplingError` on the second `next()`. Artefact:
  `tests/test_frames_ffmpeg.py`. Non-vacuity: one invocation after the first
  `next()` rejects an eager implementation; three invocations in total rejects
  one that ignores the end-of-stream rule; the cap test rejects an unbounded
  loop.

- Obligation: `L-writer-atomic`.
  Method: pytest examples: existing target without overwrite (content kept,
  `OutputExistsError`); existing target with overwrite (replaced); a write
  failure injected by monkeypatching the module's `os.link` to raise
  `OSError(errno.ENOSPC, …)` (target absent, no temporary file left). Artefact:
  `tests/test_writers_webvtt.py`. Non-vacuity: the failure test lists the
  directory and asserts it is empty, which an implementation without the
  `finally` clean-up fails.

- Obligation: `L-composition`.
  Method: pytest checks of the built service's adapter types and shared runner
  and its allowed programs; `monkeypatch.setitem(sys.modules, "cuprum", None)`
  plus removal of the cached adapter module for the capability error; and the
  shimmed BDD scenario, which goes through `build_walking_skeleton()`. Artefact:
  `tests/test_compose.py`.

- Obligation: `INV-tier-switch`.
  Method: exhaustive parameterized table (five values × four presence
  combinations) over the pure function `media_tools_status(environ, which)`,
  plus a feature-file check that both real-tool scenarios carry `@media_tools`.
  Artefact: `tests/test_media_tools_tier.py`. Non-vacuity: the table includes
  `"1"` with both tools absent (must fail, not skip) and `"yes"` (must fail
  with the usage message).

- Obligation: `INV-no-subprocess`.
  Method: an AST scan of `beatcue/**/*.py`. Artefact:
  `tests/test_no_subprocess_imports.py`. Non-vacuity: the test also runs its
  scanner on inline source strings for each forbidden form and asserts each is
  detected.

- Obligation: `REQ-proof` (end to end).
  Method: pytest-bdd scenarios with real binaries, marked `media_tools`, plus a
  CmdMox-backed twin that runs everywhere. Artefacts:
  `tests/features/walking_skeleton.feature`,
  `tests/test_walking_skeleton_bdd.py`,
  `tests/__snapshots__/test_walking_skeleton_bdd.ambr`. Evidence: the CI job
  runs `make test-media` with `BEATCUE_REQUIRE_MEDIA_TOOLS=1` and reports two
  passed, zero skipped. Non-vacuity:
  `BEATCUE_REQUIRE_MEDIA_TOOLS=1 make test-media` on this FFmpeg-less host must
  fail (negative control, recorded in `Artefacts and notes`).

### Formal verification decision

No model checking or formal proof is planned. The invariants are local,
arithmetic, or format-level, with small state; parameterized tests and
Hypothesis properties with independent oracles give proportionate confidence.
The only stateful behaviour (`L-sampler-lazy`) is a three-step sequence plus a
cap, covered exhaustively by CmdMox tests. Stronger methods would not cover the
real risk, which lies at the FFmpeg boundary and is exercised by the
media-tools tier.

### Suggested BDD features

Feature file: `tests/features/walking_skeleton.feature`, driven by
`tests/test_walking_skeleton_bdd.py`. Step functions parse `rgb(r,g,b)` tokens
into one value object to stay within Pylint's four-argument limit.

```gherkin
Feature: Real-I/O walking skeleton
  BeatCue can probe a real video, sample one frame, and write a one-cue
  WebVTT file through its domain, application, and adapter boundaries.

  @media_tools
  Scenario: Real tools turn a generated video into a one-cue WebVTT file
    Given a generated solid-colour video of rgb(51,102,204)
    When the walking skeleton writes cues to "cues.vtt"
    Then "cues.vtt" starts with the WebVTT signature
    And "cues.vtt" contains exactly one cue from "00:00:00.000" to "00:00:00.250"
    And the cue payload has kind "keyframe" and id "cue_000001"
    And the cue payload mean colour is within 12 of rgb(51,102,204)

  Scenario: Shimmed tools exercise the same path without real binaries
    Given a placeholder video file
    And ffprobe is shimmed with the captured solid-colour document
    And ffmpeg is shimmed to write a 64 by 48 frame of rgb(49,100,201)
    When the walking skeleton writes cues to "cues.vtt"
    Then "cues.vtt" matches the walking-skeleton snapshot

  Scenario: A missing ffprobe fails before any output is written
    Given a placeholder video file
    And no ffprobe executable is on the PATH
    When the walking skeleton writes cues to "cues.vtt"
    Then the run fails with a command-unavailable error naming "ffprobe"
    And "cues.vtt" does not exist

  @media_tools
  Scenario: A non-media file is rejected by the real probe
    Given a text file disguised as "not-media.mp4"
    When the walking skeleton writes cues to "cues.vtt"
    Then the run fails with a media-probe error that reports exit status 1
    And "cues.vtt" does not exist
```

The two `@media_tools` scenarios request the `require_media_tools` fixture. The
generated video comes from a session-scoped fixture that runs
`ffmpeg -nostdin -hide_banner -loglevel error -f lavfi -i
color=c=0x3366cc:s=64x48:r=4:d=1 -c:v mpeg4 -q:v 2 -pix_fmt yuv420p -an -y
<tmp>/solid.mp4`
through a `CuprumCommandRunner` allowed `{"ffmpeg"}` (probe P8).

`REQ-probe`, `REQ-sample`, `REQ-cue`, and `REQ-write`; the shimmed scenario
covers `REQ-boundaries` and `L-composition` on every host; the two failure
scenarios cover `REQ-failures` (the existing-output case is covered by
`L-writer-atomic` and the application tests). All scenarios land in `EP-M5`.

   ```plaintext
   ffprobe -v error -of json -show_entries
     format=duration:stream=index,codec_type,width,height,avg_frame_rate,r_frame_rate,duration:stream_disposition=attached_pic

   ```

   `REQUIRED_PROGRAMS = frozenset({"ffmpeg"})`,
   `FfmpegFrameSampler(runner, *, timeout_seconds=30.0, max_samples=2400)`,
   whose per-frame command vector is:

   ```plaintext
   ffmpeg -nostdin -hide_banner -loglevel error -ss <t:.6f> -i <absolute source path>
     -frames:v 1 -an -f image2 -c:v ppm -pix_fmt rgb24 -update 1 -n <tmp>/frame.ppm
   ```

   `<tmp>` is a fresh `tempfile.TemporaryDirectory(prefix="beatcue-frame-")`

## Idempotence and recovery

All steps are re-runnable. `uv lock` and `uv sync` are idempotent. Snapshot
regeneration overwrites `.ambr` files deterministically; review diffs before
committing. Temporary probe files live under `/tmp` and are deleted after
`EP-M0`. Each milestone is one or more commits that can be reverted
independently; CI and Makefile changes are isolated in `EP-M5` commits. If a
gate creates an ANSI-named directory, delete it and re-run with
`env -u FORCE_COLOR`.

## Interfaces and dependencies

No new third-party distributions. Cuprum (via the `core` extra) is imported
only in `commands_cuprum.py`. Elsewhere only the standard library is used
(`dataclasses`, `enum`, `fractions`, `json`, `math`, `os`, `pathlib`,
`tempfile`, `typing`, `asyncio`, `importlib`).

Domain signatures (all frozen, slotted, keyword-only dataclasses):

```python
# beatcue/domain/media.py
```

`Cue.__post_init__` sorts and validates the pairs (unique names, finite feature
values) and uses `object.__setattr__` to store the normalized tuples. The
remaining design §7 fields (`annotation`, `objects`, `diagnostics`,
`configuration`, `feature_summaries`, `feature_series`, `is_complete`) and the
cue-sorting invariant are deliberately deferred to roadmap 2.1.1, which extends
these same keyword-only classes; no alias or shim is introduced.
