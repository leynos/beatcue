## Purpose / big picture

BeatCue is a Python library (and, later, a command-line tool) that analyses a
short video and writes time-coded cue sheets: WebVTT metadata cues, BeatCue
JSON, and later OpenTimelineIO markers. Its architecture is hexagonal: a pure
domain layer owns value objects and port protocols, an application layer
orchestrates use cases through those ports, outbound adapters implement the
ports with real infrastructure (FFmpeg, OpenCV, writers), and a composition
root wires concrete adapters into application services.

Today the repository contains only the empty package skeleton (`beatcue/domain`,
`beatcue/application`, `beatcue/adapters/inbound`, `beatcue/adapters/outbound`,
`beatcue/config`), each with an empty `__all__`, plus a `beatcue.hello()`
smoke function. No port, adapter, domain value, or media file exists. The
design-stage review (`docs/beatcue-logisphere-design-stage-review.md` §4
scenario A) warned that a well-architected skeleton might never touch a real
video file; this task is the mitigation it recommended (§8 step 5).

After this change, one test and one Makefile command prove that the
architecture can touch real media and write a real cue sheet:

```plaintext
tests/fixtures/media/solid-3366cc-64x48-4fps-1s.mp4   (1.6 KB H.264 fixture)
        │
        ▼  MediaProbe port  ── FfprobeMediaProbe ── CommandRunner port ── Cuprum ── ffprobe
MediaMetadata(duration=1.0, fps=4.0, 64×48, has_audio=False)
        │
        ▼  FrameSampler port ── FfmpegFrameSampler ── CommandRunner port ── Cuprum ── ffmpeg
FrameSample(timestamp=0.0, PixelBuffer 64×48 rgb24)
        │
        ▼  application: build one synthetic cue from the sampled frame
AnalysisResult(media, cues=(Cue cue_000001 0.000→0.250 "Sampled frame",))
        │
        ▼  CueWriter port ── WebVttCueWriter
cues.vtt
```

The observable output is a WebVTT file such as:

```plaintext
WEBVTT
NOTE Generated by BeatCue

00:00:00.000 --> 00:00:00.250
{"id":"cue_000001","kind":"keyframe","label":"Sampled frame","confidence":1.0,"features":{"mean_b":201.0,"mean_g":100.0,"mean_r":49.0}}
```

The mean colour values come from real decoded pixels, so the file proves that a
frame really was sampled; the exact values depend on the FFmpeg build's colour
conversion and are asserted with a tolerance (see `Verification plan`).

Terms used throughout:

- *Port*: a `typing.Protocol` owned by `beatcue.domain` that describes a
  dependency the application needs (for example `MediaProbe`).
- *Adapter*: a class in `beatcue.adapters` that implements a port with real
  infrastructure.
- *Composition root*: `beatcue.config`, the only package allowed to import
  both application services and concrete outbound adapters.
- *Cuprum*: the typed, allowlisted subprocess library selected by design §16.
- *CmdMox*: the pytest plugin that intercepts external commands with shims on
  `PATH`, so adapter tests can verify exact argument vectors without real
  binaries.
- *Media-tools tier*: the tests marked `media_tools` that execute the real
  `ffprobe` and `ffmpeg` binaries. They skip when the binaries are absent,
  unless `BEATCUE_REQUIRE_MEDIA_TOOLS=1` is set, in which case absence fails.
- *Walking skeleton*: the thinnest end-to-end path through every layer that
  exercises real I/O. It is a proof of plumbing, not the analysis pipeline.

Preserved behaviour: `beatcue.hello()` and every existing test and gate keep
working. No public command-line interface (CLI) is added; the roadmap's "one
command or test" is met by `make test-media` and the behavioural scenario it
runs (see decision D3).

## Constraints

- Read `AGENTS.md`, the `.rules/python-*.md` guides,
  `docs/developers-guide.md`, and
  `docs/complexity-antipatterns-and-refactoring-strategies.md` before editing
  code.
- Implementation begins only after the user approves this plan.
- The dependency rule is fixed by design §5 and enforced by Hecate
  (`pyproject.toml` `[tool.hecate]`, `make check-architecture`):
  `beatcue.domain` imports only the standard library and other domain modules;
  `beatcue.application` imports only domain and application modules; outbound
  adapters import domain, application, adapter, and infrastructure modules; only
  `beatcue.config` may import both application services and concrete outbound
  adapters. Do not weaken, reorder, or add `ignore_imports` to the Hecate
  policy.
- Port names and signatures in design §8 are normative:
  `MediaProbe.probe(source: pathlib.Path) -> MediaMetadata`,
  `FrameSampler.sample(source: pathlib.Path, *, sample_fps: float) -> Iterable[FrameSample]`,
  and
  `CueWriter.write(result: AnalysisResult, target: OutputTarget) -> WriteResult`.
  `CommandRunner` is the design's named subprocess port. Do not rename these
  or change their parameters.
- Domain value objects must not carry NumPy, OpenCV, Cuprum, or other
  infrastructure types (design §§7–8; `FrameSample` holds an
  implementation-neutral pixel buffer).
- All external commands run through the Cuprum-backed `CommandRunner` adapter.
  No `subprocess`, `os.system`, or shell strings anywhere in `beatcue/` (design
  §16; developers' guide "Subprocess tooling").
- Boundary package `__init__.py` files keep `__all__: list[str] = []`;
  `tests/test_package_skeleton.py` asserts this. Public names are exported from
  submodules only.
- Every new production module declares `__all__` naming its public symbols.
  Planning probe P4 showed that the strict Skylos gate treats names in a
  module's `__all__` as live; this is how symbols that are reached only through
  the composition root stay out of `SKY-U001` findings (decision D7).
- No file may exceed 400 lines (`AGENTS.md`; Pylint `max-module-lines`).
  Respect Ruff `mccabe` max-complexity 8 and Pylint `max-args = 4`.
- Use `import msgspec` style only where msgspec is needed; this plan does not
  need msgspec (WebVTT payloads use the standard-library `json` module,
  matching design §13.2's `ensure_ascii=True`).
- Error classes end in `Error`, are raised with `raise … from …` when
  translating, and messages are assigned to a variable before raising (Ruff
  `EM`, `TRY`;
  `.rules/python-exception-design-raising-handling-and-logging.md`).
- Do not implement scope owned by later roadmap items beyond the minimum the
  skeleton needs: full domain invariants and fusion (2.1.x), BeatCue JSON
  (2.2.1), partial-output marking and the full WebVTT contract (2.2.2), the
  library writer API (2.2.3), full CmdMox fixture matrices (1.4.3), the
  production ffprobe adapter matrix (3.1.1), timestamp-faithful frame sampling
  (3.1.2), and any Cyclopts CLI (3.3.x).
- Authorized dependency changes: add the self-reference `"beatcue[core]"` to
  the `dev` dependency group so every development and CI environment has Cuprum
  (decision D5). No new third-party distribution is added.
- Authorized CI changes: install the distribution `ffmpeg` package on the
  Ubuntu runner and run `make test-media` with `BEATCUE_REQUIRE_MEDIA_TOOLS=1`

- Do not edit completed ExecPlans other than adding this plan's entry to

## Risks

- Risk: FFmpeg's YUV→RGB conversion differs between versions, so exact pixel
  values from the fixture vary across hosts. Severity: medium. Likelihood:
  high. Mitigation: the media-tools tier asserts mean colour within ±12 of the
  source colour `#3366cc` (51, 102, 204); exact values are snapshotted only for
  in-memory and CmdMox paths. Planning probe P1 observed (49, 100, 201) with
  FFmpeg 5.1.

- Risk: the media-tools tier silently skips everywhere, making the proof
  vacuous. Severity: high. Likelihood: medium. Mitigation:
  `BEATCUE_REQUIRE_MEDIA_TOOLS=1` turns a missing binary into a failure; CI
  sets it for `make test-media`; a unit test covers the skip/require switch;
  the CI step name makes the proof visible.

- Risk: Cuprum 0.1.0 decodes captured output as text and offers no binary
  capture or timeout parameter (verified in
  `.venv/lib/python3.14/site-packages/cuprum/sh.py`, `ExecutionContext` and
  `SafeCmd.run`). Severity: medium. Likelihood: certain. Mitigation: FFmpeg
  writes the sampled frame as a PPM file into a private temporary directory,
  and the adapter reads the bytes from disk (decision D2); timeouts wrap
  `SafeCmd.run` in `asyncio.wait_for`, whose cancellation makes Cuprum send
  `SIGTERM` and escalate to `SIGKILL` after `cancel_grace` (decision D6).

- Risk: CmdMox shims might not intercept commands launched by Cuprum.
  Severity: medium. Likelihood: low. Mitigation: Cuprum resolves programs by
  name through `asyncio.create_subprocess_exec`, which consults `PATH`, and
  CmdMox prepends its shim directory to `PATH`. Probe P5 in `EP-M0` confirms
  this before adapter work; if it fails, adapter tests use an injected fake
  `CommandRunner` and the escalation path in `Tolerances` applies.

- Risk: the self-referencing `beatcue[core]` entry in the `dev` group changes
  what `make build` and the CI coverage action install, and could break the
  lock or the Python 3.14 markers. Severity: medium. Likelihood: low.
  Mitigation: planning probe P3 showed `uv` locks a self-referencing extra in a
  dependency group correctly; `EP-M1` runs `uv lock --check` and the full gates
  before any adapter code.

- Risk: Skylos treats `__all__` exports as live, which could hide genuinely
  dead public names. Severity: low. Likelihood: medium. Mitigation: every
  exported name has a production caller or is part of a normative port surface;
  the `Outcomes & retrospective` review lists any exported name whose only
  callers are tests, and removes it.

- Risk: Hecate does not classify standard-library modules, so a stray
  `import subprocess` in the domain would pass `make check-architecture`.
  Severity: low. Likelihood: low. Mitigation: a unit test scans `beatcue/` for
  `subprocess` imports and fails if any appear (`INV-no-subprocess`).

- Risk: the media fixture is binary and cannot be regenerated on hosts without
  FFmpeg (this development host has none). Severity: low. Likelihood: high.
  Mitigation: commit the fixture, mark it binary in `.gitattributes`, pin its
  SHA-256 in a test, and document the exact containerized regeneration command
  in `tests/fixtures/media/README.md`.

- Risk: the GitHub-hosted `ubuntu-latest` image does not include FFmpeg
  (verified against `actions/runner-images` `Ubuntu2404-Readme.md` on
  2026-11-17), so CI needs an `apt-get` step that can fail on mirror outages.
  Severity: low. Likelihood: low. Mitigation: a single retried
  `apt-get install --no-install-recommends ffmpeg` step; failure is visible and
  does not mask other gates.

## Surprises & discoveries

- Observation: Cuprum 0.1.0 captures standard output only as decoded text
  (`ExecutionContext.encoding`, default `utf-8`, `errors="replace"`) and has no
  timeout argument. Evidence: `.venv/lib/python3.14/site-packages/cuprum/sh.py`
  lines 88–196 and 377–450 at Cuprum 0.1.0. Impact: frames cannot be piped as
  raw bytes through Cuprum without lossy decoding; decisions D2 and D6.

- Observation: FFmpeg writes nothing and exits 0 when asked for a frame past
  the end of the stream; with the `image2` muxer it does not create the output
  file at all. Evidence: planning probes P1 and P2 (`Artefacts and notes`).
  Impact: the sampler's end-of-stream rule is "exit 0 and no output file".

- Observation: `ffprobe` on a non-media file exits 1 and still prints an empty
  JSON object (`{}`) to standard output. Evidence: probe P2. Impact: the probe
  adapter must check the exit status before parsing, and must treat a document
  without a video stream as an error rather than as empty metadata.

- Observation: the strict Skylos gate treats names listed in a module's
  `__all__` as live, and reports unexported unused classes and functions.
  Evidence: probe P4. Impact: production modules export their public names;
  intermediate milestones pass `make lint` before the composition root exists.

- Observation: `make test` and the CI coverage action install only the `dev`
  dependency group, so Cuprum and Cyclopts are absent from the test environment
  today. Evidence: `Makefile` `.deps` target (`uv_gate prepare --group dev`);
  `leynos/shared-actions` `generate-coverage/scripts/run_python.py` runs
  `uv sync --inexact`. Impact: decision D5.

## Decision log

- D1. Decision: add a domain-owned `CommandRunner` port and a single
  `CuprumCommandRunner` adapter; the ffprobe probe and ffmpeg sampler depend on
  the port, not on Cuprum. Rationale: design §16 makes the subprocess boundary
  one outbound adapter and names `CommandRunner` as the replacement seam;
  design §6 lists `commands_cuprum.py`. The rejected alternative — each media
  adapter calling Cuprum directly — would duplicate catalogue, timeout, and
  error translation logic and spread subprocess concerns across adapters. The
  media adapters receive the runner by constructor injection from the
  composition root, so no adapter imports another adapter. Date/Author:
  2026-11-17, planning agent.

- D2. Decision: the walking-skeleton `FrameSampler` is `FfmpegFrameSampler`,
  which runs one `ffmpeg` invocation per sample time (`t_i = i / sample_fps`),
  asking for one frame as a binary PPM (`P6`) file in a private temporary
  directory, reading it, deleting it, and yielding a `FrameSample`. It stops
  when FFmpeg exits 0 without creating the file. Rationale: Cuprum cannot
  capture binary output (Surprises), PPM is self-describing (width, height,
  maximum value) so the sampler needs no side-channel dimensions, and
  one-invocation-per-frame keeps the generator lazy and resource-free between
  yields, so abandoning it after the first frame leaks nothing. Rejected
  alternatives: OpenCV `VideoCapture` (design §6 lists `frames_opencv.py`)
  would bypass the Cuprum boundary the roadmap asks to prove, pull the `media`
  extra into the default test environment, and inherit OpenCV's unreliable
  timestamp properties; decoding Latin-1 text back into bytes would work but
  couples correctness to a decoding trick. The per-frame process cost is
  acceptable for the skeleton; roadmap 3.1.2 owns throughput and true
  presentation timestamps and may replace this adapter. Design §6 will note
  `frames_ffmpeg.py` alongside the planned `frames_opencv.py`. Date/Author:
  2026-11-17, planning agent.

- D3. Decision: satisfy "one command or test" with the behavioural scenario
  `tests/features/walking_skeleton.feature` and the Makefile target
  `make test-media`; do not add a public CLI. Rationale: roadmap 3.3.1 owns the
  Cyclopts root command and its Rich and `--json` contracts; adding
  `[project.scripts]` now would pre-empt that design and require users' guide
  documentation of a throwaway command. The test acts as the library caller in
  design Figure 1 ("Python library caller → Application use cases"). Planning
  probe P4 removed the only technical reason to add a runtime caller early
  (Skylos liveness). Date/Author: 2026-11-17, planning agent.

- D4. Decision: introduce a `media_tools` pytest marker and a
  `require_media_tools` fixture that skips when `ffprobe` or `ffmpeg` is not on
  `PATH`, unless `BEATCUE_REQUIRE_MEDIA_TOOLS=1`, which turns absence into a
  failure. CI installs FFmpeg with `apt-get` and runs `make test-media` with
  the variable set. Rationale: the development host and the GitHub runner image
  both lack FFmpeg; a plain skip would make the proof vacuous, and a hard
  requirement would make `make test` unusable on contributor machines.
  Date/Author: 2026-11-17, planning agent.

- D5. Decision: add `"beatcue[core]"` to `[dependency-groups].dev`.
  Rationale: `make build`, `make test`, and the CI coverage action all sync
  only the `dev` group (Surprises); without Cuprum the adapters cannot be
  imported in tests. The self-reference keeps the `core` extra as the single
  source of runtime pins. Rejected alternatives: duplicating `cuprum>=0.1.0` in
  `dev` (two sources of truth) and adding `--extra core` to the Makefile (does
  not reach the shared coverage action, which runs `uv sync --inexact` without
  extras). Date/Author: 2026-11-17, planning agent.

- D6. Decision: `CommandRequest` carries an explicit `timeout_seconds`;
  `CuprumCommandRunner` wraps `SafeCmd.run` in `asyncio.wait_for` inside
  `asyncio.run` and translates `TimeoutError` into `CommandTimeoutError`.
  Rationale: design §16 requires explicit timeouts and a termination request
  before escalation; Cuprum implements termination on task cancellation via
  `ExecutionContext.cancel_grace`. The allowlist is enforced by building
  commands with `cuprum.sh.make(program, catalogue=BEATCUE_CATALOGUE)`, which
  raises `UnknownProgramError` for anything outside the catalogue; the
  context-variable allowlist (`cuprum.scoped`) is not relied upon because an
  empty parent allowlist is permissive. Date/Author: 2026-11-17, planning agent.

- D7. Decision: every new production module declares `__all__` with its
  public names; boundary `__init__.py` files stay empty. Rationale: probe P4
  (Skylos liveness via `__all__`) and the existing
  `tests/test_package_skeleton.py` contract. Date/Author: 2026-11-17, planning
  agent.

- D8. Decision: add `CueKind.KEYFRAME = "keyframe"` for the synthetic cue, and
  mark the cue synthetic in its provenance. Rationale: none of the design §7
  kinds describes "a frame was sampled here"; reusing `cut` or `caption` would
  make the skeleton lie about its evidence, and `caption` would breach the
  invariant that semantic annotations cannot create timing cues. Keyframes are
  already a design concept (§9 step 9, §12), so the member is a durable
  addition recorded in design §7 rather than a skeleton-only value.
  Date/Author: 2026-11-17, planning agent. Flagged for expert-panel review.

- D9. Decision: the WebVTT writer always emits `hh:mm:ss.ttt` timestamps,
  rounds to the nearest millisecond with ties away from zero, widens a cue
  whose rounded end does not exceed its rounded start to `start + 1 ms`, and
  escapes `>` as `>` inside JSON payloads. Rationale: the WebVTT syntax
  requires cue payloads and note text never to contain `-->`, and requires the
  end time to be greater than the start time; design §13.2 currently says
  "enforces `start <= end`", which would still admit an invalid zero-length
  cue. JSON string escaping keeps the payload valid JSON while making `-->`
  impossible. Design §13.2 is updated to say "greater than" and to record the
  widening rule. Date/Author: 2026-11-17, planning agent. Flagged for
  expert-panel review.

- D10. Decision: the writer refuses to overwrite an existing target unless
  `OutputTarget.overwrite` is true, by opening the file in exclusive-create mode
  (`"x"`), and writes UTF-8 with LF line endings. Rationale: design §18
  ("Output path exists → writer refuses to overwrite unless `--force`");
  exclusive creation closes the check-then-write race. Atomic replacement for
  overwrites belongs to 4.3.1. Date/Author: 2026-11-17, planning agent.

- D11. Decision: record decisions D1, D2, D4, D5, D6, and D9 in a new
  ADR 0011, "Walking-skeleton subprocess boundary and media-tools test tier",
  referenced from design §§8, 13.2, 16, and 17. Rationale: they change design
  guidance (sampler adapter choice, WebVTT timing rule, test tiering, CI
  prerequisites) that later roadmap items build on. Date/Author: 2026-11-17,
  planning agent.

## Verification plan

### Abstract model

The walking skeleton is a straight-line pipeline over four ports:

1. `probe(source) -> MediaMetadata m` with `m.duration_seconds > 0`,
   `m.fps > 0`, `m.width > 0`, `m.height > 0`, all finite.
2. `sample(source, sample_fps=f)` yields `FrameSample`s whose timestamps are
   `t_i = i / f` for `i = 0, 1, …` until FFmpeg reports end of stream. The
   application consumes only the first sample `s_0`.
3. `build_sampled_frame_cue(m, s_0) -> Cue c` with
   `c.time = TimeRange(t_0, min(t_0 + 1 / m.fps, m.duration_seconds))`,
   `c.id = "cue_000001"`, `c.kind = KEYFRAME`, `c.confidence = 1.0`, and
   features `mean_r`, `mean_g`, `mean_b` computed from `s_0`'s pixels.
4. `write(AnalysisResult(m, (c,)), target)` renders WebVTT text and creates
   the target file exclusively.

Failure transitions: missing executable → `CommandUnavailableError`; command
outside the catalogue → `CommandNotAllowedError`; timeout →
`CommandTimeoutError`; `ffprobe` non-zero exit, malformed JSON, or no video
stream → `MediaProbeError`; `ffmpeg` non-zero exit or malformed PPM →
`FrameSamplingError`; no first sample → `NoFrameSampledError`; existing target
without overwrite → `OutputExistsError`. All derive from `BeatCueError`.

### Invariants and lemmas

- `INV-time-range` (REQ-cue): `TimeRange(start, end)` exists only when both
  are finite and `0 <= start <= end`; otherwise construction raises
  `InvalidDomainValueError`.
- `INV-pixel-buffer` (REQ-sample): `PixelBuffer(width, height, data)` exists
  only when `width > 0`, `height > 0`, and `len(data) == width * height * 3`.
- `INV-mean-rgb` (REQ-cue): for any valid `PixelBuffer`, `mean_rgb` returns
  three values in `[0, 255]` equal to the arithmetic mean of each channel.
- `INV-cue-within-media` (REQ-cue): the synthetic cue satisfies
  `0 <= start < end <= duration` whenever `t_0 < duration`.
- `INV-ppm-roundtrip` (REQ-sample): parsing a well-formed binary PPM
  (`P6`, maximum value 255) returns exactly its width, height, and pixel bytes;
  any header that is not `P6`, any maximum value other than 255, and any
  payload length mismatch raise `FrameSamplingError`.
- `INV-probe-mapping` (REQ-probe): a well-formed ffprobe document with one
  video stream maps to `MediaMetadata` whose `fps` equals the stream's
  `avg_frame_rate` fraction (falling back to `r_frame_rate` when the average is
  `0/0`), whose duration is `format.duration` (falling back to the stream
  duration), and whose `has_audio` is true exactly when an audio stream is
  present.
- `INV-vtt-timestamp` (REQ-write): `format_timestamp(ms)` produces
  `HH:MM:SS.mmm` with at least two hour digits, and an independent parser in
  the test recovers `ms` exactly for all `0 <= ms < 10^9`.
- `INV-vtt-rounding` (REQ-write): `to_milliseconds(seconds)` differs from
  `seconds * 1000` by at most 0.5 and rounds ties away from zero.
- `INV-vtt-order` (REQ-write): every rendered cue has end strictly greater
  than start.
- `INV-vtt-payload` (REQ-write): every payload line is ASCII, contains no
  `-->`, contains no line terminator, and `json.loads` recovers the cue's id,
  kind, label, confidence, and features exactly.
- `INV-no-subprocess` (REQ-boundaries): no module under `beatcue/` imports
  `subprocess` or calls `os.system`.
- `L-sampler-lazy` (REQ-sample): `FfmpegFrameSampler.sample` invokes
  `ffmpeg` exactly once before yielding the first frame, holds no open file or
  temporary directory between yields, and stops after the first invocation that
  exits 0 without an output file.
- `L-runner-translation` (REQ-failures): `CuprumCommandRunner.run` maps a
  missing executable, an unknown program, and a timeout to the three command
  errors, and returns a `CommandOutcome` (never raises) for non-zero exits.

### Axioms (trusted, not verified here)

- `AXIOM-ffprobe-json`:
  `ffprobe -v error -of json -show_format -show_streams FILE` prints a JSON
  object with `streams` and `format` keys for valid media and exits non-zero
  for unreadable or non-media input (FFmpeg documentation, "ffprobe" writers
  section; probe P2).
- `AXIOM-ffmpeg-seek`: input seeking (`-ss` before `-i`) is frame-accurate
  when transcoding (FFmpeg wiki "Seeking", since FFmpeg 2.1).
- `AXIOM-ffmpeg-eos`: requesting one frame beyond the end of the stream exits
  0 and, with `-f image2 -update 1`, creates no output file (probe P2, FFmpeg
  5.1.9). The CI runner's FFmpeg (Ubuntu 24.04, FFmpeg 6.1) is exercised by the
  media-tools tier, which would fail if this changed.
- `AXIOM-ppm`: FFmpeg's `ppm` encoder with `-pix_fmt rgb24` writes
  `P6\n<width> <height>\n255\n` followed by `width * height * 3` bytes (probe
  P2 header dump).
- `AXIOM-cuprum`: Cuprum 0.1.0 resolves the program name on `PATH`, raises
  `FileNotFoundError` from process creation when it is missing (to be confirmed
  by P6), and terminates the child process when the awaiting task is cancelled.
- `AXIOM-cmdmox`: CmdMox shims on `PATH` intercept any process started by
  name, including Cuprum's (to be confirmed by P5).
- `AXIOM-webvtt`: the W3C WebVTT syntax (Candidate Recommendation Draft,
  revision `0648025`) requires the `WEBVTT` signature, forbids `-->` in cue
  payloads and comments, and requires cue end times greater than start times.

### Formal verification decision

No model checking or formal proof is planned. The invariants are local,
arithmetic, or format-level, with small state; Hypothesis properties with
independent oracles plus named boundary examples give proportionate confidence.

exhaustively by the CmdMox test. Stronger methods would not cover the real
risk, which lies at the FFmpeg boundary and is exercised by the media-tools
tier.
